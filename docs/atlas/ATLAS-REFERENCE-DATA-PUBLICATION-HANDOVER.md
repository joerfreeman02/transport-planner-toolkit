## Architecture

The app shell remains on the existing `transport-planner-toolkit` Pages site.
The prepared datasets are published as immutable versioned roots:

- `transport-planner-toolkit-bus-data/releases/<version>/`
- `transport-planner-toolkit-tnds-data/releases/<version>/`

That is two publication roots for the measured starting datasets. Each is
independently addressable and independently size-gated. If a future fresh
candidate exceeds the limit, the workflow stops with exact evidence rather
than truncating coverage. The resolver already supports deterministic
`pathRoots` mappings for a future logical partition, but no arbitrary split is
applied without a fresh measured dataset and Technical Director approval.

The app reads the ATLAS-level `atlasDataSources` configuration. Bus source code
does not contain production publication URLs. Local checkouts retain relative
fallback roots under `atlas/data`; deployed configuration points to immutable
external roots. Optional path mappings can route a requested shard to a
separate publication root while preserving the existing relative shard paths.

Every publication retains the existing prepared `manifest.json` and adds
`publication-manifest.json` containing publication version, source-manifest
identity, exact byte/file totals, aggregate SHA-256 and per-file SHA-256s.

## Implementation

Changed files:

- `.github/workflows/atlas-bus-data-refresh.yml` — separates app/data payloads,
  fetches last-known-good external manifests, publishes both data roots,
  waits for their Pages URLs, then uploads the small app shell.
- `atlas/config/atlas-data-sources.json` and `.mjs` — ATLAS-level local
  fallback configuration; NPTG is explicitly null.
- `src/atlas/infrastructure/atlas-data-sources.mjs` — validated base URL and
  deterministic path-root resolver.
- `src/atlas/adapters/prepared-bus-data-adapter.mjs` — accepts resolved Bus
  and TNDS file URLs; all service, stop, merge, authority and presentation
  logic is unchanged.
- `tools/atlas-data-publication/publication.mjs` — exact measurement,
  checksum manifest, publication preparation and 1 GB hard gate.
- `tools/atlas-data-publication/fetch-last-known-good.mjs` — obtains the active
  app config and only the manifests needed for freshness/baseline checks.
- `tools/atlas-data-publication/wait-for-publication.mjs` — waits for both
  immutable data roots to be served before the app config switch.
- `tests/atlas/atlas-data-publication.test.mjs` and existing contract runner —
  configured-root, external shard, failure, checksum and publication tests.

Updater behavior remains NaPTAN + BODS + TNDS acquisition, candidate
validation, deterministic tests, publication, availability verification, then
app-shell deployment. A failure before the final app deployment leaves the
previous active config untouched. Rollback is redeployment of the previous app
config; immutable data releases are retained for audit.
